**Concurrent-change abort (proven, not assumed):**
`scripts/ops/eventforge-sl-update` re-reads the live object before any mutation and aborts
unless the live ingress AND egress arrays hash exactly to the recorded values — an
unexpected concurrent security-list change therefore aborts before any write. The update
itself carries the freshly fetched ETag via `--if-match`, so a mutation racing between the
read and the write is rejected by OCI (HTTP 409) and the script surfaces it as a failure
with no auto-retry. A post-update re-read must hash to the proposed arrays or the change is
reported NOT verified. This logic is exercised offline by `tests/ci/test-sl-update-guard.sh`
(stubbed OCI; matching/stale/converged/approval-gate cases).
