## 3. Repairs (Phases 2–4, no infrastructure or state change)

All changes are verification-only, merged through a protected PR:

- `scripts/local/lib-m1.sh`:
  - `m1_state_key_status` — classifies a state-key HEAD probe as
    `exists`/`absent` (authoritative 404 only)/`auth`/`service`/`timeout`/
    `malformed`; a failed probe is never absence.
  - `m1_verify_refreshing_plan` — refuses `-refresh=false`/`-refresh-only` in
    plan/apply invocations (a reviewed plan must reflect live state).
  - `m1_plan_structure_ok` — requires valid JSON, `errored == false`, and the
    expected plan structure (omitted-empty 1.12 collections tolerated, present
    keys type-checked).
  - `m1_classify_drift` — inspects `resource_drift` explicitly and classifies
    every entry: CRITICAL (protected imported resources, including MySQL
    nsg_ids), EXPECTED_COMPUTED (budget actual/forecasted spend and its
    timestamps only), UNKNOWN (everything else, including any non-no-op
    `resource_changes` entry).
  - `m1_mysql_nsg_state_live_agree` — independent read-only comparison of RAW
    state vs live db-system `nsg_ids`; fails on any disagreement or
    unparseable input.
- `scripts/local/m1-verify.sh`: drift gate validates the plan structure, then
  classifies drift; CRITICAL/UNKNOWN fail acceptance; expected computed drift
  is reported as **acknowledged drift** (never silent zero). New gate
  `mysql-nsg-state-vs-live` fails while state and live disagree. Platform
  state absent (established deployment) or unclassifiable fails.
- `scripts/local/m1-platform-{plan,init}.sh`, `m1-preflight.sh`: state-key
  presence classified; auth/service/timeout/malformed HEAD outcomes fail
  closed instead of reading as absence/fresh-state.
- `scripts/local/m1-platform-apply.sh` + `m1-local.env`: the dedicated
  MYSQL-NSG-RETEST gate — a plan reviewed against
  `platform-safe-plan-mysql-retest-policy.json` requires the separate
  `GATE: MYSQL-NSG-RETEST` approval (never a general `PLATFORM-APPLY` record),
  the saved plan is revalidated offline against the dedicated policy, plan
  before/after must equal the reviewed policy values, and the LIVE db system
  must be ACTIVE with exactly the reviewed before-value `nsg_ids`.
- `tests/local/test-m1-local-guards.sh`: ten regression scenarios covering all
  mission Phase 5 cases (wired into CI via `tests/ci/run.sh`).
